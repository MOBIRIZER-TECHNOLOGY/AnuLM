## Review fixes (2026-11-01)

- **E1 budgets.** "The budgets alone set the mixture" replaced: English and Hindi web stop at
  their budgets; Hindi Wikipedia and Python are `1e12`, so their shares come from the data on
  disk. The budget is checked after each batch of 1,000 documents (`build_v2.py` line 119), so
  sources overshoot: English +573,711, Hindi web +23,402 tokens, printed by
  `ch21_measure_corpus.py` (it reads `build_v2.SOURCES` itself).
- **E2 int64.** The reason is now measured: `ch21_windows.py` tries int64/int32/uint16 ids on
  `F.embedding` and `F.cross_entropy` (torch 2.11): int32 works for the embedding only, uint16 for
  neither. Code and output quoted in 21.4.
- Remainder: the 160 unseen tokens without replacement are now broken down by the example: 64 in
  the one skipped window (1,561 windows, 195 batches of 8), 42 before the offset, 54 after the grid.
- `epochs_done` (lines 139–141) defined in 21.6.
- Duplicates: only documents agreeing in their first 200 characters share a side;
  near-duplicates differing there can land in both splits.
- "A window costs about 2 KB" now says the OS reads at least one 4 KB page for 2,050 bytes.
- Tokenizer file: the build encodes with `release/AnuLM-Base-400M/tokenizer.json` (line 42),
  recorded in its docstring as identical to `bpe.py`; `meta.json` names `data/multi32k.json`.
- "micro-batch" defined in 21.1; "pinned memory" defined where first used (21.4).
- Restored the two excerpts cut for pages earlier (`build_v2.py` 134–138, `train.py` 510–515).
